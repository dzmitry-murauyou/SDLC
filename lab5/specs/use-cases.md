# Актёры и спецификации вариантов использования Guardian

> Базовые прецеденты трассируются к SRS Guardian. UC-11 — только учебное Change-01 из ЛР №4 и не является требованием базового SRS.

## Актёры

| Актёр | Роль |
|---|---|
| Пользователь | Владелец локального хранилища; создаёт и открывает его, управляет записями, выбирает резервирование и явно инициирует передачу секрета. |
| USB-ключ FIDO2/WebAuthn | Внешний аппаратный фактор, отвечающий на запрос проверки при создании/разблокировке в пределах поддерживаемого протокола. |
| Утверждённый браузер Windows | Получает только выбранные пользователем поля после успешной проверки источника автозаполнения. |
| Windows | Операционная система, предоставляющая блокировку сеанса, файловые диалоги и системный буфер обмена. |
| Файловая система / внешний накопитель | Среда, в которой пользователь вручную выбирает место сохранения или файл зашифрованной копии. |

## UC-01 — Создать хранилище и зарегистрировать первичный ключ

**Назначение.** Начальная локальная настройка Guardian с мастер-паролем и зарегистрированным USB-ключом.

**Предусловия.** Локальное хранилище ещё не создано; совместимый FIDO2-ключ доступен; пользователь управляет устройством.

**Основной поток.** 1) Пользователь запускает создание хранилища. 2) Guardian запрашивает мастер-пароль и его подтверждение. 3) Пользователь подключает ключ и подтверждает регистрацию по протоколу. 4) Guardian проверяет успешный ответ ключа. 5) Приложение создаёт защищённое локальное хранилище и завершает настройку в состоянии Locked либо открывает его только после успешной проверки требуемых факторов.

**Альтернативы/ошибки.** A1: мастер-пароли не совпадают — запись не создаётся, пользователь получает сообщение без раскрытия введённого секрета. A2: ключ не найден, регистрация отменена или проверка неуспешна — настройка не считается завершённой. E1: ошибка сохранения — нет частично созданного доступного хранилища.

**Постусловия.** При успехе существует локальное защищённое хранилище и зарегистрированный ключ; секреты доступа не записаны открытым текстом. При отказе хранилище не разблокировано.

## UC-02 — Разблокировать хранилище

**Назначение.** Предоставить доступ к локальным записям после проверки обоих факторов.

**Предусловия.** Хранилище создано и находится в состоянии Locked; доступен зарегистрированный FIDO2-ключ.

**Основной поток.** 1) Пользователь вводит мастер-пароль. 2) Guardian проверяет его и запрашивает подтверждение зарегистрированного USB-ключа. 3) Пользователь подтверждает запрос на ключе. 4) Guardian проверяет ответ обоих факторов. 5) При успехе приложение открывает хранилище и показывает список без раскрытия секретных полей.

**Альтернативы/ошибки.** A1: неверен мастер-пароль, ответ ключа отсутствует/некорректен либо пользователь отменил запрос — Guardian остаётся Locked и показывает нейтральную ошибку. E1: ошибка чтения/проверки хранилища — данные не показываются.

**Постусловия.** Успех переводит хранилище в Unlocked; неуспех оставляет его Locked. Успешная проверка одного фактора не заменяет второй.

## UC-03 — Управлять обычными записями

**Назначение.** Создавать, просматривать, изменять, искать и удалять записи и защищённые заметки.

**Предусловия.** Хранилище Unlocked.

**Основной поток.** 1) Пользователь выбирает создание или изменение записи. 2) Вводит название, логин, пароль, URL/идентификатор источника, категории и дополнительные поля. 3) Guardian валидирует и сохраняет запись в локальном хранилище. 4) Пользователь ищет запись по допустимым несекретным полям или просматривает список. 5) Удаление требует явного выбора.

**Альтернативы/ошибки.** A1: запись не проходит проверку — сохранение не выполняется, причина показана без секретных значений. A2: поиск не дал результатов — отображается пустое состояние; пароль и заметки не появляются в поисковой выдаче. E1: ошибка записи не должна приводить к незаметной частичной потере данных.

**Постусловия.** При успехе изменение сохранено локально и доступно после повторного открытия; удалённая запись не появляется в обычном списке.

## UC-04 — Сгенерировать пароль

**Назначение.** Создать пароль с заданной длиной и классами символов.

**Предусловия.** Пользователь находится в интерфейсе Guardian; для сохранения результата открыта целевая запись.

**Основной поток.** 1) Пользователь задаёт длину от 8 до 128 и нужные классы символов. 2) Guardian проверяет настройки и использует криптографически стойкий источник случайности среды Java. 3) Приложение показывает сгенерированный результат или позволяет поместить его в выбранное поле.

**Альтернативы/ошибки.** A1: длина вне диапазона или несовместимые параметры — генерация отклоняется с понятным сообщением. E1: недоступен источник случайности — пароль не создаётся предсказуемым способом.

**Постусловия.** Пароль создан по указанным настройкам и не передан внешнему сетевому сервису.

## UC-05 — Просмотреть TOTP-код

**Назначение.** Рассчитать одноразовый код для сохранённого аккаунта внешнего сервиса.

**Предусловия.** Хранилище Unlocked; в записи пользователя сохранён TOTP-секрет.

**Основной поток.** 1) Пользователь открывает настройки TOTP записи. 2) Guardian локально вычисляет код по параметрам записи и RFC 6238. 3) UI показывает код и время до его смены. 4) Пользователь скрывает поле либо блокирует хранилище.

**Альтернативы/ошибки.** A1: секрет или параметры некорректны — код не показывается. E1: ошибка вычисления не раскрывает TOTP-секрет в сообщении.

**Постусловия.** Код доступен только в разблокированном UI; TOTP для сторонних аккаунтов не заменяет FIDO2-фактор самого Guardian.

## UC-06 — Хранить и явно использовать wallet-secret

**Назначение.** Сохранить предоставленные пользователем данные криптокошелька и по запросу раскрыть или скопировать секрет.

**Предусловия.** Хранилище Unlocked; пользователь имеет собственные метаданные и seed-фразу/приватный ключ для ручного внесения.

**Основной поток.** 1) Пользователь создаёт wallet-запись и вводит метаданные и секрет вручную. 2) Guardian сохраняет данные в зашифрованном локальном хранилище. 3) Секрет остаётся замаскированным. 4) Для показа или копирования пользователь выполняет отдельное явное действие. 5) Guardian временно показывает/копирует выбранный секрет согласно правилам UI/буфера обмена.

**Альтернативы/ошибки.** A1: пользователь отменяет ввод — запись не создаётся. A2: хранилище заблокировано — раскрытие/копирование недоступно. E1: ошибка сохранения не оставляет секрет в открытом журнале/диагностике. E2: недоступен blockchain/RPC-интерфейс — такая операция не предусмотрена.

**Постусловия.** Успешная запись хранится локально и шифруется; никакого получения баланса, создания кошелька, подписания или отправки транзакций не выполняется.

## UC-07 — Безопасно заполнить запись в браузере

**Назначение.** Передать только выбранные пользователем поля на подтверждённый источник.

**Предусловия.** Хранилище Unlocked; запись имеет источник; поддерживаемый браузер доступен.

**Основной поток.** 1) Пользователь выбирает запись и явно запускает автозаполнение. 2) Guardian проверяет схему, хост и эффективный порт текущего адреса. 3) После возможного перенаправления адрес проверяется повторно. 4) Если контекст соответствует записи, передаются только выбранные поля.

**Альтернативы/ошибки.** A1: иной/неоднозначный источник, поддельный домен, другой порт или схема — Guardian отказывает и не передаёт секрет. A2: браузер не входит в подтверждённую матрицу — операция отклоняется.

**Постусловия.** Либо выбранные поля переданы в проверенный контекст по явной команде, либо секрет не передан.

## UC-08 — Создать зашифрованную резервную копию

**Назначение.** Сохранить ручной зашифрованный файл Guardian.

**Предусловия.** Хранилище Unlocked; пользователь выбрал создание копии и доступный путь.

**Основной поток.** 1) Guardian собирает данные хранилища, включая wallet-secrets. 2) Применяет утверждённый криптографический механизм (конкретная схема выбирается по ADR-0002 до релиза). 3) Создаёт файл собственного формата по выбранному пользователем пути. 4) Сообщает результат без вывода секретов.

**Альтернативы/ошибки.** A1: пользователь отменяет выбор файла — экспорт отменён. E1: ошибка создания файла — неполная копия не объявляется успешной; открытые секреты не записываются в другой файл.

**Постусловия.** При успехе существует зашифрованная ручная копия; автоматической синхронизации нет.

## UC-09 — Восстановить резервную копию

**Назначение.** Проверить выбранный файл и перенести данные в другой экземпляр Guardian.

**Предусловия.** Пользователь явно выбрал файл и целевой экземпляр; для целевой конфигурации выполнена утверждённая процедура аутентификации/регистрации факторов.

**Основной поток.** 1) Guardian читает выбранную копию. 2) Проверяет формат, доступ и целостность до изменения действующих данных. 3) Пользователь подтверждает восстановление. 4) Приложение импортирует записи, включая wallet-secrets, в локальный Vault. 5) Guardian требует штатную MFA для последующего разблокирования.

**Альтернативы/ошибки.** A1: повреждённый, неизвестный формат, неверный пароль или отмена — восстановление не выполняется. E1: текущий Vault не заменяется до успешной проверки копии. E2: восстановление не может обходить обязательную MFA.

**Постусловия.** Успех восстанавливает данные в целевом Guardian; отказ оставляет существующее состояние без изменений.

## UC-10 — Заблокировать хранилище

**Назначение.** Прекратить доступ к расшифрованным данным после явной команды либо системного события Windows.

**Предусловия.** Хранилище Unlocked.

**Основной поток.** 1) Пользователь нажимает «Заблокировать» или Windows сообщает о блокировке/завершении сеанса. 2) Guardian скрывает секреты и отзывает доступ UI к открытым данным. 3) При возможности Windows очищает связанный с Guardian секрет в буфере обмена. 4) Следующее открытие требует UC-02.

**Альтернативы/ошибки.** A1: ОС не позволяет очистить буфер — Guardian предупреждает пользователя и предоставляет явное действие очистки. E1: повторная аутентификация не пройдена — состояние остаётся Locked.

**Постусловия.** Хранилище Locked; секреты не доступны через обычные экраны. Тайм-аут бездействия не задаётся этой базовой спецификацией.

## UC-11 — Зарегистрировать запасной FIDO2-ключ (Change-01, учебное расширение)

**Назначение.** В рамках сценария ЛР №4 разрешить предварительно зарегистрировать второй ключ, не меняя базовый SRS Guardian.

**Предусловия.** Change-01 отдельно принят владельцем продукта; пользователь разблокировал Vault основными факторами; доступен новый совместимый ключ. В базовом релизе этого прецедента нет.

**Основной поток.** 1) Пользователь открывает управление зарегистрированными факторами. 2) Guardian требует штатное подтверждение действующего доступа. 3) Пользователь инициирует регистрацию запасного ключа и подтверждает его на устройстве. 4) Guardian проверяет регистрацию и сообщает о результате. 5) Разблокировка по-прежнему требует мастер-пароль и любой из зарегистрированных ключей.

**Альтернативы/ошибки.** A1: регистрация отменена или ключ не поддерживается — список не меняется. A2: попытка доступа без мастер-пароля или с незарегистрированным ключом отклоняется. E1: потеря обоих ключей не покрывается Change-01 и требует отдельной утверждённой процедуры восстановления.

**Постусловия.** В учебном сценарии второй ключ добавлен и проверен; в базовом SRS ничего не меняется до формального согласования и обновления требований.
